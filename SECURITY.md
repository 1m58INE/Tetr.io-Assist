## Reporting a problem

If the repository has **GitHub private vulnerability reporting** enabled, use its **Security → Report a vulnerability** interface. If it is not enabled, **there is no designated private reporting channel**. Do not publish exploits, credentials, identifying user information, or reproducible attack payloads in public issues or pull requests. A report does not imply that anyone will review, respond to or fix it.

For a security issue in **TETR.IO itself**, contact the TETR.IO operator using its official support/security channels rather than this repository: [TETR.IO support](https://tetr.io/about/support/).

## Research boundaries

- Work only with locally owned code and **offline, isolated, synthetic test fixtures**.
- Do not perform exploitation, load testing, scanning, scraping or intrusive testing against TETR.IO, live services, or other players.
- Do not test anti-cheat bypass, account restrictions, unauthorized access or service safeguards.
- Do not include secrets, personal information, or unauthorized third-party artifacts in reports or contributions.
- Stop and follow the relevant operator's published policies if an issue could affect a live service.
